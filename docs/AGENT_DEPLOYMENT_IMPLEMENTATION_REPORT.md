# Agent Deployment Implementation Report — Phase F

## Package structure

The existing `sih26-26153` package now has a setuptools build backend and the
existing `sentinel-agent` console entry point. The agent implementation remains
under `src.agent`; no second package was introduced.

## CLI

Implemented commands are `init`, `register`, `start`, `stop`, `restart`,
`status`, `config`, `config validate`, `diagnostics`, and `service` with
`install`, `uninstall`, `start`, `stop`, `restart`, and `status` actions.

## Configuration and secrets

Configuration is JSON in an OS-appropriate application-data directory and is
overridable with `SENTINEL_AGENT_HOME` or `SENTINEL_AGENT_CONFIG`. It covers
server, identity, protocol/schema, capture, telemetry, heartbeat, retry,
buffer, logging, and environment settings. Runtime credentials are separated
into a sibling credential file, atomically written and permission-restricted
where supported. Windows ACL hardening remains an operator responsibility.

## Lifecycle and capture

Startup validates configuration, identity, HTTPS policy, writable storage,
Scapy/Npcap/libpcap availability, and the selected interface before capture
starts. SIGTERM/SIGINT initiate capture shutdown and practical telemetry flush.
Process, capture, connection, and telemetry status are reported separately.

## Services and deployment

Linux has a real per-user systemd unit generated by `service install`.
Windows service installation is explicitly unsupported in this release; an
approved host service manager is required. The agent requires outbound
connectivity only and never proxies customer application traffic.

## Version and compatibility

Agent version `0.2.0`, protocol version `1`, telemetry schema version `1`, and
the central model version remain distinct. The agent does not silently alter
the frozen 17-feature, L=10, K=5 forecasting contract.

## Limitations

Windows-native service installation, automatic credential renewal, OS vault
integration, mTLS/OIDC, shared HA runtime storage, and physical host reboot
testing remain future work. The central runtime rebuilds forecast history after
restart, as documented.
